# Internationalization (i18n) — Elemnt Rentals

This document defines how multi-language support is implemented in the frontend.

Elemnt Rentals must support:
- English (en)
- Spanish (es)

All user-facing content must be rendered using translation keys.

---

## Translation System

The frontend must use a dictionary-based translation system.

No text may be hardcoded in components.

All strings must be loaded from language dictionaries.

---

## Dictionary Structure

Translation files must be stored in:

/locales/
├── en.json
└── es.json

Each file contains the same keys.

Example:

en.json
```json
{
  "home": {
    "hero_title": "Premium Short-Term Rentals",
    "hero_subtitle": "Fully managed, higher returns"
  },
  "property": {
    "book_whatsapp": "Book via WhatsApp"
  }
}

es.json
{
  "home": {
    "hero_title": "Rentas vacacionales premium",
    "hero_subtitle": "Gestión completa, mayor rentabilidad"
  },
  "property": {
    "book_whatsapp": "Reservar por WhatsApp"
  }
}
```

## Key Naming Convention

All translation keys must follow this format:


## Examples

- `home.hero_title`
- `property.book_whatsapp`
- `owner.cta_list_property`
- `admin.property_save`

## This ensures

- Predictable structure  
- Easy search  
- AI compatibility  

---

# Language Detection

The frontend should determine the active language based on:

- URL (`/en`, `/es`)
- Browser preference
- **Default fallback:** English

---

# WhatsApp & External Links

When generating WhatsApp links, the selected language must be passed so that:

- Message templates  
- Auto-filled text  

appear in the correct language.

---

# Future Extensions

The i18n system must be designed to support:

- Additional languages  
- Country-specific wording  
- A/B testing of copy  
  without changing UI code.

---

# Non-Compliance

Any component that renders hardcoded text is considered **invalid** and must be **rejected**.
